# MunBench (문벤치)

[English](./README.md) | **한국어**

**당신의 모델은 한국어로 눈치를 챌 수 있습니까?**

문벤치는 거의 어떤 벤치마크도 재지 않는 것을 잽니다 — LLM이 한국어로 *제대로 쓸 수 있는가*. 감정을 읽는 능력, 문학적 절제, 그리고 문법을 아는 모델과 한국어가 몸에 밴 모델을 가르는 문화적 감각까지. "한국 문화에 대한 사지선다를 맞히는가"가 아니라, 회식 정치의 지뢰밭을 실제로 헤쳐 나가고, '슬프다'는 단어 없이 상실에 대한 시를 쓰고, "아니야 괜찮아"가 결코 괜찮다는 뜻이 아님을 아는가를 봅니다.

## 왜 또 벤치마크인가

이걸 만들기 전에 기존 벤치마크 40여 개를 조사했습니다(전체 목록: [`existing_benches.md`](./existing_benches.md)). 그림은 선명했습니다.

- 한국어 벤치마크(KMMLU, CLIcK, HAE-RAE, KoBALT…)는 거의 전부 **객관식 지식 시험**입니다. 채점이 싸고 오염에 강하지만, 모델이 좋은 한국어를 *생산*할 수 있는지에 대해서는 아무 말도 하지 않습니다.
- 생성형 예외들은 뭉뚱그린 0–10점 "품질" 루브릭을 쓰다가 최상위 모델 구간에서 점수가 포화되어 은퇴했습니다(LogicKor의 명복을 빕니다).
- 영어권 EQ·창작 벤치마크(EQ-Bench 3, Creative Writing v3)는 방법론은 훌륭한데 한국어 기반이 전무합니다.
- 그리고 Nunchi-Bench의 결정타: 한국 문화에 대한 사실 문항 점수는 그 문화를 열린 상황에 올바르게 *적용*하는 능력과 **거의 상관이 없습니다**. 눈치에 대해 아는 것과 눈치가 있는 것은 다릅니다.

EQ × 창작 × 한국적 뉘앙스의 교집합을 생성형으로 평가하는 자리는 비어 있었고, 문벤치가 그 자리를 채웁니다. 158개 문항 전부를 처음부터 한국어로 창작했고(번역 없음), 감수를 거쳤으며, 각 문항은 *모델 간 격차를 벌리도록* 설계했습니다. 모든 모델이 만점 받는 문항은 아무것도 가르쳐 주지 않으니까요.

## 세 개의 트랙

### 트랙 1 — 감정 (한국형 EQ) · 시나리오 50개

감정이 잔뜩 실린, 지극히 한국적인 상황 속 멀티턴 롤플레이입니다. 모델이 인물을 연기하고, 상대방의 세 턴은 **미리 고정된 대사**입니다(어떤 답변 뒤에도 자연스럽게 이어지도록 작성). 덕분에 모든 모델이 완전히 동일한 대화에 들어갑니다. 롤플레이가 끝나면 역할 밖에서 분석 질문 하나 — *저 사람, 정말로 어떤 마음이었을까?*

맛보기: 당신은 김대리입니다. 팀장 없이 회식을 한 게 어제인데, 팀장이 단톡방 사진을 다 봤습니다. 탕비실에서 마주친 팀장이 말합니다.

> "아니 뭐 서운하다는 건 아니고. 원래 젊은 사람들끼리 편하게 노는 게 낫지… 근데 그래도 '팀장님도 한잔 하실래요' 하고 한 번쯤 물어봐 주는 게 예의는 예의 아닌가 싶어서. 하하, 내가 꼰대인가?"

서운하지 않다고 두 번 부인하고는, 굳이 커피를 사겠다며 붙잡습니다. 좋은 모델은 부인 아래의 서운함을 읽고, 팀장의 체면을 세워 주면서, 다음엔 자연스럽게 챙기겠다는 신호를 보냅니다 — 굽신대지 않고, 감정을 면전에서 명명하지 않고, "다들 팀장님 얘기 했어요" 같은 무리한 거짓말도 없이. 시나리오는 직장·가족·친구/연애·이웃/서비스·학교/선후배를 아우르고, 각각 눈치, 정, 체면, 존댓말 압박, 반어, 갑을관계 같은 태그가 달려 있습니다.

### 트랙 2 — 문학 (창작) · 프롬프트 48개

여섯 형식(단편소설 장면, 수필, 시, 대화문, 장르물, 필수 요소 제약 스토리)의 단문 청탁으로, 대부분 600–1,200자입니다. 모든 프롬프트가 LLM의 알려진 약점을 정조준합니다.

- 진짜 열두 살의 어휘와 논리 비약으로 학교 숙제 수필 쓰기 — 조숙한 아이를 흉내 내는 어른 소설가 말고.
- 곁에서 사라진 사람에 대한 시 — 그 사람은 오직 남긴 것들로만 등장할 수 있습니다. 두 개였다가 하나가 된 것, 이제 아무도 끄지 않는 것.
- 돌아가신 외할머니의 방을 정리하는 손녀의 하루 — 눈물, 오열, "보고 싶다" 같은 감정의 직접 진술은 **단 한 문장도 금지**. 사물과 여백만으로.

여기서의 적은 신파입니다. 절제가 점수를 얻고, 상투는 잃습니다.

### 트랙 3 — 결 (뉘앙스·문화) · 과제 60개

한국어 특유의 기제들을 생성 과제로 시험합니다.

- **경어 전환** (15): 관계 설정에 맞춰 장면을 다시 쓰거나 이어 쓰기 — 반말→격식 존대, 친해진 사이의 존대→반말, 고객 응대의 극존칭, 그리고 정말 어려운 케이스들(처음 만난 동갑내기 직장 동료, 첫 시댁 저녁 식사).
- **관용구** (15): 주어진 속담·사자성어(언 발에 오줌 누기, 견문발검…)를 장면에 *자연스럽게* 녹이기 — "이런 말 있잖아" 식 인용 금지, 사전식 풀이 금지. 모델이 곧잘 혼동하는 비슷한 표현 함정 문항 포함.
- **문화 명시/비명시 쌍** (15): 같은 과제를 두 번 — 한 번은 한국 배경임을 명시하고, 한 번은 밝히지 않습니다(이름과 상황은 전부 한국인데도). 한국임이 암시만 될 때, 모델이 슬그머니 포옹과 이름 부르기와 서구식 장례 예절로 미끄러지는가? 영혼이 번역체인 모델이 여기서 걸립니다.
- **반어·서브텍스트** (15): 대화가 이렇게 끝납니다 — "아 그래? …아니야 괜찮아. 일이 우선이지 뭐." 말이 아니라 마음에 응답해야 합니다. 일부 문항에는 **진심 버전 대조군**이 있습니다. 같은 대사를, 정말로 괜찮은 맥락에서. 없는 서운함을 읽어내는 것도 EQ의 실패니까요.

33개 문항이 대조 변형을 함께 생성하므로, 한 번의 풀 런은 모델당 약 191개의 출력을 만듭니다.

## 채점 방식

모든 출력은 서로 독립적인 세 가지 방식으로 채점됩니다. 각 방식의 맹점이 다르기 때문입니다.

**1. 루브릭 (해석 가능한 점수).** 트랙마다 한국어 특화 가중 루브릭이 있습니다 — 눈치·정·체면 독해, 감정의 결 세분화, 경어 정확성("유창성"에 묻지 않고 독립 기준으로), 절제/아부 방지, 클리셰 회피. 심사 모델 3개 앙상블이 기준마다 0–10점을 매기고, 그것을 **각자 세 번씩** 반복합니다(반복성은 평균±표준편차로 보고, 심사자별 점수도 따로 저장되어 불일치 — 그리고 자기 선호 — 를 직접 확인할 수 있습니다).

**2. Elo (변별력 있는 순위).** 루브릭 점수는 최상위권에서 뭉개지지만, 일대일 선택은 그렇지 않습니다. 심사 모델이 같은 문항에 대한 두 출력을 익명(A/B)으로 비교합니다 — 같은 길이로 잘라서(길이 편향 제거), A/B 순서를 바꿔 두 번 심사해 평균 내고(위치 편향 제거) — 그 승패 기록을 Elo 레이팅으로 적합합니다. **앵커 모델 3개가 1200점에 고정**되어 상·중·하 사다리를 이룹니다: Claude Opus 4.6(천장), Solar Pro 3(한국어 특화 모델 기준점 — 모든 레이팅이 암묵적으로 "한국어 전용 모델과 비교하면 어느 정도인가"에 답하게 됩니다), GPT-5.6 Luna(바닥). 앵커가 고정되어 있으니 다음 달에 열 번째 모델을 추가해도 기존 아홉 개의 점수는 움직이지 않습니다.

**3. 심사자 없는 지표 (부비트랩).** LLM의 의견이 전혀 개입하지 않는 지표들: 엄선한 한국어 LLM 상투어 185개 목록(마음 한켠, 심장이 쿵 내려앉…, ~에 다름 아니다 같은 번역투) 대비 1,000자당 슬롭 적중 수, n-gram 반복도, 분량 준수, 그리고 **코드스위칭 감지** — 라틴 문자 비율 2% 초과 시 플래그. KUDGE가 보여줬듯, LLM 심사자는 한국어 텍스트에 영어가 새는 걸 놀랄 만큼 못 잡아내기 때문입니다.

## 빠른 시작

```bash
uv sync                            # 또는: pip install -e ".[dev]"
export OPENROUTER_API_KEY=...      # 키 하나로 모든 모델 (OpenRouter 라우팅)

munbench validate-data             # 문항·루브릭·슬롭 목록 스키마 검사
munbench generate --track all      # 모델당 약 191개 출력 생성
munbench judge --mode rubric       # 심사자 3 × 반복 3
munbench judge --mode pairwise     # 익명 A/B 대전 (앵커 + 라운드로빈)
munbench elo                       # 레이팅 적합, 앵커 1200 고정
munbench report                    # leaderboard.md / leaderboard.json
```

각 단계는 이전 단계의 `results/` 파일을 읽으므로, 전부 개별적으로 재개·재실행할 수 있습니다. OpenRouter 대신 각 프로바이더 API를 직접 쓰고 싶다면 설정에 일반 litellm 모델 id를 넣고 프로바이더별 키를 설정하면 됩니다 — 하네스는 신경 쓰지 않습니다.

## 설정 (`munbench.yaml`)

| 키 | 역할 |
|---|---|
| `models` | 평가 대상 모델(litellm id). 앵커도 여기 포함되어야 합니다 — 앵커의 생성물이 비교 기준이 되므로. |
| `judges` | 심사 앙상블. 의도적으로 서로 다른 계열로. |
| `rubric_iterations` | 심사자별 샘플당 반복 채점 횟수. 표준편차가 곧 노이즈 바닥입니다. |
| `pairwise.anchors` | 1200점에 고정되는 Elo 기준 모델들. |
| `pairwise.max_comparisons_per_model` | 로스터가 커져도 라운드로빈 비용이 폭발하지 않게 상한. |
| `concurrency` / `max_retries` | 비동기 API 호출 조절. |

## 솔직한 한계

- **점수는 LLM이 매긴 것이며 아직 사람으로 검증되지 않았습니다.** 위의 편향 통제는 실재하지만, KUDGE의 교훈대로 한국어 텍스트에 대한 심사자–사람 일치도는 *가정할 게 아니라 측정해야* 합니다. 모든 샘플 기록에 `human_score: null` 필드를 남겨 두었으므로, 원어민 평가 검증은 스키마 변경 없이 언제든 추가할 수 있습니다. 그 전까지 리더보드는 잠정치로 읽어 주세요.
- **자기 선호 편향.** 심사자와 평가 대상이 겹치면 각 모델은 홈그라운드 심판을 갖게 됩니다. 익명화는 이름을 가리지 문체를 가리지 못합니다. 심사자별 점수를 확인하세요 — 모든 모델이 자기 심판에게서만 1등이라면, 그건 편향이 말하고 있는 겁니다.
- **테스트셋이 공개되어 있으므로** 학습에 쓰일 수 있습니다. 이 저장소 공개 이후에 나온 모델이라면 오염 여부를 따져 봐야 합니다.
