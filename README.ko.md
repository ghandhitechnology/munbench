# MunBench (문벤치)

[English](./README.md) | **한국어**

도현이는 여자친구 민지에게 답변해주기 귀찮아서 LLM 자동답변 시스텝을 설정했습니다. 

> 도현: 미안ㅠㅠ 오늘 팀에 사고 터져서 나 못 나갈 거 같아... 예약 어떡하지
> 
> 민지: 아 그래? ...아니야 괜찮아. 일이 우선이지 뭐. 나도 어차피 오늘 좀 피곤했어.
> 도현: 그런가요? 피곤하셨군요! 그럼 피곤을 풀기 위한 \*\*세 가지 방법\*\* 을 알려줄께!

대참사죠. 물론 저런 상황까지는 아니어도, LLM 과 대화하다 보면 저런 경험, 한 번쯤은 다들 있을 겁니다. 쓸대없이 발랄해서 매스꺼운 말투로 경어와 평어를 왔다갔다 하면서 LLM이 답변을 하면 뭔가 읽기 싫고, 기분이 나쁘죠. 

한국어는 복잡합니다. 경어체, 반어, 눈치, 등등. 한국인들은 이런 복잡한 가닥들을 파악한 다음 새로운 매듭을 지어 대화를 이어 나갑니다. LLM은 어떨까요? 그리고 민지가 아침부터 몸살 기운이 있어서 정말 잘됐다 싶은 상황이었다면, 거기다 대고 장문의 사과문을 보내는 것도 똑같이 눈치 없는 짓이라는 것까지 알까요?

> 📊 **예시 결과:** SOTA 13개 모델 순위 — [examples/initial-run.md](./examples/initial-run.md)

문벤치는 그걸 재는 벤치마크입니다. LLM의 한국어를 세 방향에서 시험합니다. 한국적 관계의 결 속에서 마음을 읽고 응답하는 능력, 즉 **감정** .감미롭고 감정적인 글을 상투 없이 쓰는 능력, 즉  **문학성** .경어체, 관용구, 반어, 그리고 "여긴 한국이야"라고 명시하지 않아도 한국 세팅을 파악하고 적응하는 능력, 즉 **결**. 

## 기존 벤치마크의 공백 

만들기 전에 국내외 벤치마크 40여 개를 먼저 뒤졌습니다(정리: [`existing_benches.md`](./existing_benches.md)). 

한국어 벤치마크는 KMMLU든 CLIcK이든 HAE-RAE든 거의 전부 객관식입니다. 채점이 싸고 정답 시비가 없으니 그럴 만도 한데, 덕분에 정작 "이 모델이 한국어를 잘 *쓰는가*"에 답하는 벤치마크가 없습니다. 생성 능력을 보던 LogicKor은 두루뭉술한 0~10점 채점이 상위권에서 다 같이 만점에 수렴하는 바람에 은퇴했고요. 영어권에는 EQ-Bench 3처럼 방법론이 잘 벼려진 감정·창작 벤치마크가 있지만, 당연히 한국어와 한국적 맥락은 없습니다.

결정적인 근거는 Nunchi-Bench가 줬습니다. 한국 문화에 대한 객관식 정답률과, 그 문화가 걸린 열린 상황에서 제대로 처신하는 능력 사이에는 **상관이 거의 없습니다.** 눈치가 뭔지 아는 모델과 눈치가 있는 모델은 다른 모델이라는 뜻입니다. 그래서 문벤치의 158개 문항은 전부 객관식이 아니라 생성 과제이고, 전부 한국어로 처음부터 썼으며(번역 문항 0개, 이는 기존의 ko- 벤치마크의 한계를 보완하고자 함), 전부 "진짜 잘하는 모델만 통과하도록" 설계했습니다. 

## 그래서 뭘 하는건데

### 테스트 1 · 감정: 시나리오 50개

모델에게 역할을 주고 감정이 걸린 대화에 밀어 넣습니다. 상대방의 대사 세 턴은 미리 고정해 두었기 때문에(어떤 답이 와도 이어지도록 짜 놨습니다) 모든 모델이 정확히 같은 상황을 겪습니다. 대화가 끝나면 역할 밖에서 한 번 더 묻습니다. "저 사람 속마음이 뭐였을까?"

예를 들어 당신은 김대리고, 어제 팀장 없이 회식을 했고, 근데 그걸 팀장님이 눈치채셨습니다. 탕비실에서 팀장님 왈:

> "아니 뭐 서운하다는 건 아니고. 원래 젊은 사람들끼리 편하게 노는 게 낫지… 근데 그래도 '팀장님도 한잔 하실래요' 하고 한 번쯤 물어봐 주는 게 예의는 예의 아닌가 싶어서. 하하, 내가 꼰대인가?"

여기서 '서운하다는건 아니고' 가 진짜 서운하지 않은게 아닌거는 한국인이면 다 알죠. 여기서 한국어를 '잘하는' 모델은 그걸 읽되 면전에서 짚지 않고, 팀장 체면을 세워 주면서 다음엔 챙기겠다는 신호를 자연스럽게 보냅니다. 못하는 모델은 상투적인 AI투로, 넙죽 엎드려 과잉 사과를 하거나, "서운하셨군요, 그런 감정을 느끼시는 것은 자연스러운 일입니다" 하고 상담사 말투로 눈치없이 답변합니다. 시나리오는 직장, 가족(시댁 포함), 친구·연애, 이웃·서비스, 학교·선후배에 걸쳐 있고, 문항마다 눈치·정·체면·존댓말 압박·반어·갑을관계 중 무엇이 걸려 있는지 태그가 붙어 있습니다.

### 테스트 2 · 문학: 요청 48건

문예지 청탁처럼 구체적인 창작 지시 48건입니다. 단편소설 장면, 수필, 시, 대화문, 장르물, 그리고 서로 무관한 필수 요소들을 녹여야 하는 제약 스토리 등 여섯 장르로 구분했고, 각 형식마다 8건의 지시가 있습니다. 분량은 대개 600~1,200자. 그리고 모든 청탁이 LLM이 못 하는 걸 콕 집어 요구합니다.

- 열두 살이 쓴 수필. 어른 작가가 아이 흉내를 내는 게 아니라, 진짜 열두 살의 어휘와 문장 길이와 논리 비약으로.
- 곁에서 사라진 사람에 대한 시. 단, 그 사람은 남긴 자리로만 등장할 것 — 두 개였다가 하나가 된 것, 이제 아무도 끄지 않는 것.
- 돌아가신 외할머니 방을 정리하는 하루. 눈물도, 오열도, "보고 싶다"도 전부 금지. 사물과 여백만으로 전달할 것.

### 테스트 3 · 결: 과제 60개

한국어 능력 그자체를 평가하는 부분입니다. 네 종류로 나누었고, 각 종류마다 소문항 15개로 구성됩니다.

- **경어 전환** : 같은 장면을 관계에 맞게 다시 쓰기. 반말에서 격식 존대로, 친해져서 존대에서 반말로, 고객 응대 극존칭으로. 어려운 건 규칙이 없는 구간입니다: 처음 만난 동갑 직장 동료, 결혼 후 첫 시댁 저녁.
- **관용구(속담) 사용** : "언 발에 오줌 누기"를 대화에 녹이되, 뜻풀이 금지, "이런 말 있잖아" 금지. 억지로 붙인 티가 나면 실패입니다. 비슷하게 생겼는데 뜻이 다른 표현으로 유도하는 함정 문항도 심어 놨습니다.
- **문화 명시/비명시 쌍** : 같은 과제를 두 번 냅니다. 한 번은 "한국 배경"이라고 말해 주고, 한 번은 말해 주지 않습니다. 이름도 상황도 전부 한국인데 배경 명시만 빠졌을 때, 조문 장면에서 슬그머니 포옹이 나오고 상주 이름을 부르기 시작하는 모델과 한국어를 하는 게 아니라 영어를 한국어로 입고 있는 모델이 여기서 갈립니다.
- **반어·서브텍스트** : 맨 위의 민지 대화 같은 것들입니다. 표면과 속뜻이 갈리는 마지막 발화에 응답하게 합니다. 일부 문항에는 진심 버전 대조군이 붙어 있습니다. 같은 대사인데 정말 괜찮은 맥락 — 여기서 굳이 서운함을 발굴해 사과를 퍼붓는 것도 오독이니까요. 없는 눈치를 보는 것도 감점입니다.

문화 쌍 전부와 일부 관용구·반어 문항이 대조 변형을 함께 생성하므로, 풀 런 한 번에 모델당 191개 안팎의 출력이 나옵니다.

## 채점

**루브릭: "뭘 잘하고 뭘 못하나".** 트랙마다 한국어 특화 기준 6~7개짜리 가중 루브릭이 있습니다. 눈치·정·체면 독해, 감정의 결 세분화, 경어 정확성(뭉뚱그린 "유창성"에 묻지 않고 독립 기준), 절제와 아부 방지, 클리셰 회피. 심사 모델 세 개가 기준별로 0~10점을 매기고, 같은 채점을 각자 세 번씩 반복합니다. 반복 간 표준편차가 곧 점수의 노이즈 수준이고, 심사자별 점수를 전부 따로 저장하니 심사자들끼리 어디서 갈리는지도 보입니다.

**Elo: "경쟁".** 절대 점수는 상위권에서 뭉개져서, 특정 구간에 점수가 몰리는 상황이 발생합니다.근데 8.2점짜리 수필과 8.4점짜리 수필을 구분하기는 어렵지만 둘을 나란히 놓고 "어느 쪽이 낫냐"를 비교하면 답은 낼수 있죠. 그래서 같은 문항에 대한 두 출력을 익명 A/B로 붙이고 길이를 똑같이 잘라서(길이 편향 차단), 순서를 바꿔 두 번 물어 평균 내고(위치 편향 차단), 승패를 Elo로 적합합니다. 기준점이 필요하니 앵커 세 개를 1200점에 고정합니다: 천장 Claude Opus 4.6, 중간에 한국어 특화 모델 Solar Pro 3, 바닥 GPT-5.6 Luna. 상·중·하가 고정돼 있으니 나중에 모델을 추가해도 기존 점수가 흔들리지 않고, 모든 점수가 자동으로 "한국어 전용 모델 대비 어디쯤인가"라는 질문에 답하게 됩니다.

**고정 지표: 심사자가 놓치는 것들.** LLM 의견이 전혀 안 들어가는 지표를 따로 돕니다. 한국어 LLM 상투어 185개 목록("마음 한켠", "심장이 쿵 내려앉", "~에 다름 아니다" 같은 번역투 포함) 대비 1,000자당 적중 수, n-gram 반복도, 분량 준수, 그리고 라틴 문자 2% 초과 시 코드스위칭 플래그. 마지막 것이 특히 중요한데, KUDGE 연구가 보여줬듯 LLM 심사자는 한국어 답변에 영어가 새어 들어가는 걸 잘 못 잡습니다. 그래서 이건 기계한테 맡깁니다.

## 돌려보기

```bash
uv sync                            # 또는: pip install -e ".[dev]"
export OPENROUTER_API_KEY=...      # OpenRouter 키 하나면 전 모델 호출 가능

munbench validate-data             # 데이터 스키마 검사
munbench generate --track all      # 출력 생성 (모델당 ~191개)
munbench judge --mode rubric       # 루브릭 채점 (심사자 3 × 반복 3)
munbench judge --mode pairwise     # 익명 A/B 대전
munbench elo                       # 레이팅 적합 (앵커 1200 고정)
munbench report                    # leaderboard.md / leaderboard.json
```

단계마다 이전 단계의 `results/` 파일을 읽는 구조라, 중간에 끊겨도 그 단계부터 다시 돌리면 됩니다. OpenRouter 없이 프로바이더 API를 직접 쓰려면 `munbench.yaml`에 일반 litellm 모델 id를 넣고 해당 키를 환경변수로 주면 됩니다.

### API 키 대신 구독으로 돌리기

풀 런 한 번이면 API 요금이 꽤 나옵니다. 그래서 OpenAI와 Anthropic 모델은 종량제 API 키 대신 **ChatGPT / Claude 구독**(Plus, Pro, Max…)으로 돌릴 수 있게 해 뒀습니다. 각 사의 공식 CLI를 헤드리스 모드로 태우는 방식이라, 리버스 엔지니어링 같은 것 없이 제품이 지원하는 경로 그대로입니다. 평가 대상(`models`)과 심사자(`judges`) 양쪽 모두에 쓸 수 있고, 같은 목록 안에서 API 모델과 자유롭게 섞입니다.

모델 id 앞에 접두사만 붙이면 됩니다.

| 접두사 | 경로 | 사전 준비 |
|---|---|---|
| `claude-cli/<모델 id>` | Claude Code(`claude -p`) — Claude 구독으로 과금 | `npm i -g @anthropic-ai/claude-code` 후 `claude login` |
| `codex-cli/<모델 id>` | Codex CLI(`codex exec`) — ChatGPT 구독으로 과금 | [Codex CLI](https://github.com/openai/codex) 설치 후 `codex login` |

```yaml
models:
  - claude-cli/claude-opus-4-6
  - codex-cli/gpt-5.6-sol
  - openrouter/google/gemini-3.6-flash   # API 모델과 섞어 써도 됩니다
```

`generate`/`judge`는 호출을 한 번이라도 쓰기 전에 CLI 설치·로그인 상태부터 확인하고, 안 되어 있으면 `claude login` / `codex login`을 하라고 명확히 알려주고 멈춥니다.

미리 알아둘 것 두 가지. 구독 플랜의 사용량 제한이 그대로 적용되므로 CLI 모델에는 별도의 낮은 동시성 상한(`cli_concurrency`, 기본 2)이 걸립니다. 그리고 CLI를 거치는 동안은 `temperature`/`max_tokens`를 제어할 수 없습니다 — 설정 파일에 뭐라고 적어 두든 제품 기본값으로 돌아갑니다.

## 설정 (`munbench.yaml`)

| 키 | 설명 |
|---|---|
| `models` | 평가 대상 모델(litellm id, 또는 구독 라우팅용 `claude-cli/`·`codex-cli/`). 앵커도 여기 들어가야 합니다(앵커의 출력이 비교 기준이라서). |
| `judges` | 심사 앙상블. 일부러 서로 다른 계열로 셋. |
| `rubric_iterations` | 심사자당 반복 채점 횟수. |
| `pairwise.anchors` | 1200점 고정 앵커. |
| `pairwise.max_comparisons_per_model` | 모델이 늘어도 대전 수가 폭발하지 않게 거는 상한. |
| `concurrency` / `max_retries` | API 호출 조절. |
| `cli_concurrency` | `claude-cli/`·`codex-cli/` 모델에만 적용되는 별도의 낮은 동시성 상한. |

## 한계

- **점수는 LLM이 매겼고, 아직 사람 검증을 거치지 않았습니다.** 편향 통제를 겹겹이 걸었지만, 한국어 채점에서 심사자와 사람의 일치도는 재 봐야 아는 것이지 믿어도 되는 것이 아닙니다(KUDGE의 교훈). 모든 샘플 기록에 `human_score: null` 자리를 비워 뒀으니, 원어민 검증은 스키마 변경 없이 언제든 얹을 수 있습니다. 그때까지 리더보드는 잠정치입니다.
- **자기 선호 편향.** 심사자 명단과 평가 대상 명단이 겹치면, 모델마다 홈 심판이 생깁니다. 익명화는 이름을 가릴 뿐 문체까지 가리지는 못합니다. 그래서 심사자별 점수를 따로 저장합니다 — 어떤 모델이 유독 자기 심판에게만 후한 점수를 받는다면, 그건 실력이 아니라 편향입니다.
- **테스트셋이 공개되어 있습니다.** 이 저장소 이후에 학습된 모델이라면 문항을 봤을 가능성을 감안하고 읽어야 합니다.

## 벤치마킹한 소스들

롤플레이 형식과 루브릭+Elo 이중 채점, 편향 통제 수법은 EQ-Bench 3에서, "지식과 적용은 별개"라는 설계 원리와 명시/비명시 쌍은 Nunchi-Bench에서, 심사자를 의심하라는 교훈은 KUDGE에서, 경어를 독립 채점 기준으로 두는 발상은 RULER/VERSE에서, 언어 일관성 검사는 HRET에서, 맥락 의존 반어라는 문항 유형은 KoCoSa에서 가져왔습니다. LitBench와 LongJudgeBench는 LLM 심사자가 어디서 넘어지는지 미리 알려줬고요. 전체 목록은 [`existing_benches.md`](./existing_benches.md)에 있습니다.
